# README for HUMANS


## Short steps to setup ccoreconf project

Assuming your *pwd* is multi_sid/

Set up two directories in your project, one to store model files which contain the SID files and the data instance in JSON Format, the other folder will contain the autogenerated stubs
```
$ mkdir model/ stubs/
# Set up python projects if you need to generate stubs. 
$ python -m venv myenv
$ source myenv/bin/activate
$ pip install -r requirements.txt # For running generateStubs.py and prepareModel.py
```

## Generation of Stubs using generateStubs.py

Generate stubs with "test-schc" as the namespace for given *non-overlapping* SID files
```
python ../../tools/generateStubs.py test-schc \
          -f ./model/ietf-schc@2023-01-28.sid ./model/ietf-schc-oam@2021-11-10.sid 
```

This script creates two sets of \*.c and \*.h files. First set is \*.handlers.c/.h which contains autogenerated getters/setters methods to access node leafs based on SIDs. You *mustn'nt* edit them!
The second set of \*.c and \*.h is \*-impl.c/.h which contains human readable methods which MUST BE edited to implement your business logic. They will automatically call the appropriate getters/setters automatically.

## Preparing your data instance and key SID data to be embedded in your C Project using prepareModel.py

It turns SID files plus an instance JSON into <name>.c and <name>.h. Those hold the SID, key-mapping and parent tables and the instance CBOR (encoded by pycoreconf). a

```
python ../../tools/prepareModel.py \
          --sid-files model/ietf-schc@2023-01-28.sid model/ietf-schc-oam@2021-11-10.sid \
          --instance  model/schc.json \
          --name      test-schc \
          --output-dir include_model
```

You can check main.c to see how to include the model, crawl and query through the resultant *CoreconfModelT* object containing data instance, key mapping and other information.
